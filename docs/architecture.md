# FX Chart Analyst — current architecture

Status of the running tree, not a plan. `main` at `ef5a808` matches `origin/main`. The Worker, package, and workflow are `fx-chart-analyst`. The repo folder is still `browser-run-poc`.

The other files in `docs/` are historical. `gap-analysis.md`, `implementation-plan.md`, and spec v4 still describe a JavaScript capture worker with analysis not started. That work is in this tree. Spec v3 (OpenAI file search) was dropped and must not be implemented. This document is the current system.

## Purpose

Every weekday at 07:00 UTC (09:00 SAST) the Worker reads two livecharts.co.uk pages, clips the embedded TradingView widget, and asks `deepseek-flash` to apply a written order-flow method. It does not pull prices, indicators, or news. The only market evidence is the PNG. If a level, session, or confirmation is not on an image, the method requires `NOT VISIBLE`, and any mandatory checklist miss forces stand aside.

The two assets are fixed:

| Asset | Page |
|---|---|
| `nasdaq100` | `https://www.livecharts.co.uk/MarketCharts/nasdaq100.php` |
| `gold` | `https://www.livecharts.co.uk/MarketCharts/gold.php` |

Daily capture is `1D`, `30m`, and `3h`. The widget label map also has `1W`, `1M`, `3M`, and `1Y` for manual screenshots. `15m` is not in that map, so it is never requested. If the menu has no `3 hours`, capture may fall back to `30 minutes` and record that. If `30m` was already stored, the fallback is refused so the run does not save the same image twice.

## Request path

`scheduled()` does not capture or call the model. It only starts a workflow and returns.

```
cron 0 7 * * 1-5
  scheduled()
    startDaily({ date, force:false, assets:[nasdaq100, gold], phase:"full", runId:"cron-DATE" })
      Workflow instance id = cron-DATE

for each asset:
  capture-ASSET-1D      browser step, own retry budget
  capture-ASSET-30m
  capture-ASSET-3h
  analyse-prepare-ASSET read PNGs from KV
  analyse-chat-ASSET    DeepSeek
  analyse-chat-retry    only if content empty or finish_reason=length
  analyse-parse-ASSET   Zod, stamp, write JSON + Markdown + run log
  analyse-chat-correct  only if JSON/schema failed and the first chat was usable
  analyse-parse-retry
  brief-ASSET           phone HTML

notify-morning          one Telegram message for both assets
```

Manual entry points use the same workflow.

- `GET` or `POST /run?token=…` is phase `full`: capture, then analyse. Optional `asset`, `date`, `force=1`.
- `GET` or `POST /analyse?token=…` is phase `analyse`: re-read PNGs already in KV. No browser.

Instance ids are the idempotency key:

| Call | Id |
|---|---|
| Weekday cron, or manual `/run` with both assets and no `force` | `cron-YYYY-MM-DD` |
| `/analyse` one asset, no force | `analyse-{asset}-{date}` |
| `/analyse` both assets, no force | `analyse-{date}` |
| Anything with `force=1` | `run-{sanitized runId}`, and the run id includes `Date.now()` |

`create()` on an existing id is caught and turned into `get()`. A second cron the same day, or a manual `/run` without `force`, does not start a second run. It returns the existing instance with `created: false`. A failed morning run is not replayed by hitting `/run` again unless `force=1`, which mints a new id. A run id starting with `cron-` cannot force, even if the payload says `force: true`. `normalizeParams` enforces that.

Wrong or missing `token` on `/reports`, `/brief`, `/run`, and `/analyse` is **404**, not 401. Comparison is length-aware and constant-time.

## HTTP surface

Ungated:

- `GET /` — JSON index of decisions and routes.
- `GET /status` — `puppeteer.limits` and `puppeteer.sessions`.
- `GET /cleanup` — connect to each session and close it.
- `GET /screenshot?asset=&timeframe=` — live clipped PNG, not stored. Defaults `nasdaq100` / `1D`. Checks the browser time quota first and returns 429 if acquisitions or remaining time are exhausted.
- `GET /latest?asset=&timeframe=` — `{asset}/{timeframe}/latest.png` from KV.

Token-gated:

- `GET /reports?token=` — date list, newest first, from `reports/{asset}/{date}.json` keys.
- `GET /reports/:asset/:date?token=` — rendered HTML of the Markdown report.
- `GET /reports/:asset/:date/:tf.png?token=` — dated PNG.
- `GET /brief/:asset/:date?token=` — phone brief. `no-store`, `nosniff`, `no-referrer`.
- `/run` and `/analyse` — 202 with `{ id, created }`, or 400 for a bad date or asset.

`/status`, `/cleanup`, `/screenshot`, and `/latest` have no token. `/screenshot` spends browser time. `/cleanup` closes sessions. That is the main exposed operational surface.

Supported manual timeframes on `/screenshot` and `/latest`: `30m`, `3h`, `1D`, `1W`, `1M`, `3M`, `1Y`. Assets: `nasdaq100`, `gold`. Dates must be real `YYYY-MM-DD` UTC dates.

## Capture

`src/capture/browser.ts` launches a browser per timeframe step, not one session for all three frames of an asset. Viewport is 1440×900. Navigation waits for `domcontentloaded`, 30 seconds. A stylesheet hides consent and high-z fixed overlays, then waits 3 seconds.

Interval selection, inside the TradingView frame (`s.tradingview.com/widgetembed` or any `tradingview.com` frame):

1. If the checked toolbar radio or legend already matches the requested label or token (`1D`, `D`, `30`, `3h`, `180`, and the rest of `INTERVAL_BUTTON_TOKENS`), keep it.
2. Else click the toolbar radio whose `aria-label` equals the full label (`1 day`, `30 minutes`, `3 hours`).
3. Else open `[aria-label="Chart interval"]` and click a menu row. Menu items prefer `[data-qa-id="interval-menu-item"]`, then `div[role="row"]`.
4. Read the interval back. The chart box must be at least 600×300. The PNG IHDR must say the same. The clip is capped at 1200×700. SHA-256 must not match a prior frame in this asset run.
5. One in-page reselect if any of those fail. Then the frame is a miss.

Workflow retries a miss twice, 20 seconds exponential, 4 minute step timeout, unless the note contains `duplicate`. Quota, missing KV, a bad asset, or an empty timeframe list are fatal: remaining timeframes for that asset are skipped. A non-fatal miss still continues, and analysis runs on whatever was stored. Zero stored frames skips analysis and writes a terminal failure.

If `force` is false and the dated PNG is already in KV, that step does not open a browser. Cached frames are treated as interval-verified. Width and height are not re-read from metadata. A cached hash that matches an earlier timeframe in the same run is dropped as a duplicate.

Quality is `ok` only when every requested timeframe was stored and interval-verified. Anything less is `poor`. The report then withholds bias and the trade plan.

`/screenshot` calls the same capture with `force: true` and `store: false`, and returns the bytes. It does not write KV.

Size constants live in `src/capture/config.ts`: minimum 600×300, clip maximum 1200×700.

## Analysis

Three workflow steps so a model retry does not share a CPU budget with parsing.

### Prepare

Step `analyse-prepare-{asset}`, 1 retry, 2 minutes.

Skip if `reports/{asset}/{date}.json` exists and `force` is false. Otherwise load stored PNGs. Zero images is a hard fail (`no screenshots in KV`). A PNG under 600×300, fewer than three images, or a poor capture sets `hintPoor`, which the stamper writes as `capture_quality: "poor"` even if the model says `ok`.

When `phase` is `analyse`, there is no capture result. Prepare loads `1D`, `30m`, and `3h` directly from KV for that date.

### Chat

Step `analyse-chat-{asset}`, 1 retry, 30 seconds constant, 10 minute timeout.

Raw `POST https://api.deepseek.com/chat/completions`. No SDK, no tools, no `json_schema`, no temperature. The model must be exactly `deepseek-flash`. `deepseek-v4-flash`, `deepseek-v4-flash-vision-exp`, and `deepseek-v4-pro` are refused. `medium` effort is coerced to `high`. Unknown effort values fall back to `high`.

The body is:

- **system:** methodology, then context, then output rules, then one example JSON object. Text only. Images in system messages are a DeepSeek 400.
- **user:** `Image i of n — {label}`, then `data:image/png;base64,…` with `detail: "original"`, then the run context last (asset, date, requested vs actual timeframes, capture notes). That ordering keeps the system prefix stable for DeepSeek's prompt cache.
- `response_format: { type: "json_object" }`, `thinking: { type: "enabled" }`, `reasoning_effort`, `max_tokens: 16384`.

429 and 5xx retry. Other 4xx, a missing key, and a refused model become `NonRetryableError`. Empty content or `finish_reason: "length"` is unusable: one extra chat step (`analyse-chat-retry-{asset}`), then a failure run log. The raw completion is parked at `drafts/{asset}/{date}/completion.json` so the parse step does not call the model again.

Screenshots stay PNG. They are base64-encoded per chat step from the KV bytes, not passed through workflow step state. Step results must stay small; image bytes are not in them.

### Parse

Step `analyse-parse-{asset}`, 1 retry, 10 seconds, 2 minutes.

Strip a markdown fence if present, `JSON.parse`, coerce, Zod-parse.

Coercion is the tolerance layer, not the schema:

- unknown `capture_quality` becomes `poor`
- a string in `confluence` or `conflicts` becomes `{ claim, timeframes: [] }`
- a string in `invalidation` becomes `{ condition, level: null }`
- timeframe level objects (`{ name, price }`, or `label` / `value` / `level`) become `"name price"`
- non-string `structure`, `wick_extremes`, and `notes` are coerced the same way

Schema version is `"2"`. After a successful parse the Worker overwrites identity fields the model must not own: `schema_version`, `prompt_version` (`"2"`), `model`, `generated_at_utc`, `asset`, and the capture block's requested timeframes, actual timeframes, quality, and notes. A JSON or Zod failure on the first usable completion gets one correction turn (`analyse-chat-correct-{asset}`): the validation message is appended and the model must return one JSON object, no fence. A second failure is terminal. If the first chat was already a retry for unusable content, a schema failure is terminal immediately (`allowRetry` is false).

Empty `method_citations` on an `ok` capture is a grounding warning, logged and webhooked, but the report is still stored. Unknown section headings are recorded on the run log, not rejected. A poor capture also webhooks. `FAILURE_WEBHOOK_URL` failures are swallowed so a dead webhook cannot fail the run.

`analyseAsset()` in `src/analysis/analyse.ts` is the same pipeline without workflow steps. The cron path does not call it.

## The method, and why verdicts lean stand-aside

`knowledge/methodology.md` is the decision procedure. `knowledge/context.md` is reference only: trend, candle definitions, confluence, and risk arithmetic. Both are in the system message. The procedure wins if they conflict. Citable headings are every `##` in both files.

Procedure headings:

- Inputs
- Ground rules
- HTF bias and dealing range
- ITF phase and alignment
- STF sessions liquidity and traps
- ETF inducement and confirmation
- Trade plan
- Final verdict

The procedure is an institutional order-flow checklist. Trade ATS supplies the cycle (contraction, expansion, trend). Liquidity and inducement supply execution. The Asia session range is treated as the daily contraction box. London or New York sweep of Asia or prior-day liquidity is expansion. Displacement after the sweep is the trend.

Mandatory checklist items, each `PASS`, `FAIL`, or `NOT VISIBLE`:

- HTF bias is clear, and price is in the correct half of the range
- Qualified POI, all three filters pass
- ITF phase supports the trade
- Inducement: liquidity swept inside the POI
- Key time window is active
- Lower-timeframe confirmation formed
- T2 meets the minimum reward to risk (1:3)

Any `FAIL` or `NOT VISIBLE` means `verdict.direction = stand_aside` and `grade = NO TRADE`. A+ is fresh context and every item PASS, risk 1%. B is mature context and every item PASS, risk 0.5%. Secondary flags (news proximity, spread, late entry, T3 not visible) must be stated and do not by themselves block a trade.

The procedure's chart roles are daily or 4 hour, 1 hour, 15 minute, and 1 minute (5 minute allowed for confirmation). The capture does not take those frames. It takes `1D`, `30m`, and `3h`. Session windows, a 15-minute ATR stop buffer, and 1-minute confirmation are therefore usually `NOT VISIBLE`. A correct model read of this capture set should stand aside more often than it should print a trade. That is the method, not a capture bug. News is never in the capture, so the prompt says to write `news not checked`.

Levels that cannot be read must be null. Estimates must contain `(est.)`. The example JSON in the prompt is a shape fixture (`asset: "example"`) and is parsed at module load so a schema drift fails the build. Output rules also require `verdict.direction` of `long`, `short`, or `stand_aside`, and `bias.direction` of `bullish`, `bearish`, `neutral`, or `unclear`. The schema is wider than the prompt on bias (`up`, `down`, `mixed` are also accepted).

Context headings, citable but not decisive: Core framework, Market structure, Candlestick signals, Chart formations, Confluence and entry, Risk arithmetic, Liquidity traps. Context's minimum reward-to-risk note is 1:2. The procedure requires T2 of at least 1:3. The procedure wins.

## What a human sees

### Full report

`src/report/render.ts` writes Markdown. `src/report/html.ts` renders a small subset: headings, lists, blockquotes, images, horizontal rules, inline code, and bold. Model text is escaped. Image refs like `./1D.png` are rewritten to `/reports/{asset}/{date}/1D.png?token=…`.

A poor capture prints a warning and omits Bias and Verdict. Timeframes, confluence, conflicts, invalidation, citations, confidence, and caveats still render. An ok capture with no citations prints a grounding warning and still shows the verdict. Every report ends with a fixed disclaimer: model commentary from images and a written method, not investment advice, not verified against price data. The page is `noindex`. The report page does not set `no-store`. The brief does.

### Phone brief

`src/report/brief.ts`. Written only after a successful analysis, in its own workflow step (1 retry, 10 seconds, 1 minute). If that step fails, the asset is marked not ok and the morning message says there is no brief.

The page is light/dark, safe-area padded, `noindex`, `no-store`, `nosniff`, `no-referrer`. It shows verdict, grade, confidence, reason, checklist, chart images, conflicts, invalidation, and caveats. Images are loaded in the page by appending `?token=` from the query string. The token is also embedded in the inline script as a fallback. `writeBrief` rewrites `generated_at_utc` to `{date}T00:00:00.000Z` before render so image paths use the report date, not the model's timestamp. Asset labels are `Gold` and `Nasdaq 100`.

The range rail is not a schema field. `extractRange` scans rationale, verdict reason, and timeframe text for phrases like `range ~4,050–4,650`, `external range high`, `range low`, `equilibrium`, and `last daily close` / `current daily close` / `current close` / `daily close`. If low, high, equilibrium, and close all parse and high is greater than low, the brief draws a discount/premium bar. Close below equilibrium is discount, above is premium, equal is equilibrium. Telegram uses the same parser. If the model does not use those phrases, the rail is absent and the rest of the brief still renders.

### Telegram

`src/notify.ts`. One message after every workflow, including failures. The notify step retries twice, 20 seconds apart, 1 minute timeout.

Heading is the report date at 07:00 UTC formatted in `Africa/Johannesburg`, so `2026-10-16` becomes `Fri 16 Oct · 09:00 SAST`. Each asset is `GOLD` or `NASDAQ`, then `LONG` / `SHORT` / `STAND ASIDE`, grade, a bias line, an optional range line, checklist counts, a clipped reason, and the brief URL. A failed asset is `{NAME} · no brief` plus the error, and the token is not included. Text is cut at 3900 characters. `disable_web_page_preview` is set. The bot token is redacted from Telegram error bodies before they are thrown.

If a successful asset's JSON is not readable yet, the step throws `report not visible yet` so the workflow retries. If the JSON fails schema parse, that asset is rewritten as a failure inside the message rather than failing the workflow.

Missing Telegram secrets log `telegram.skipped` and return `{ sent: false }`. That does not fail the run.

## Workflow failure behaviour

Per asset, capture and analysis are independent. Nasdaq failing does not skip gold.

| Failure | What is recorded | Morning message |
|---|---|---|
| No stored frames | `recordTerminalFailure`, run log, optional webhook | `{NAME} · no brief` |
| Thrown analysis error | same, step `analyse-failed-{asset}` | same |
| Unusable completion after the extra chat | `recordUnusable`, draft deleted | same |
| Schema failure after the correction turn | run log with the raw content, draft deleted | same |
| Brief write fails | asset marked not ok, no extra failure record beyond the thrown step | same |
| Analysis succeeds, citations empty, capture ok | report stored, grounding warning, webhook | normal brief link |
| Analysis succeeds, capture poor | report stored, bias and verdict withheld in Markdown, webhook | normal brief link, verdict still in the JSON the digest reads |

The workflow return value is `{ date, runId, results }` where each result is `{ asset, ok, skipped? }`. `skipped` is true when a report already existed and analysis was not re-run. The brief step still runs in that case, because skip happens inside analysis and the brief step is after it. A skipped analysis does not refresh the JSON. The brief is rewritten from the existing report.

`notify-morning` always runs after the asset loop, including when every asset failed.

## Security

- Gated routes use a timing-safe compare and return 404, so a missing token is indistinguishable from a missing report.
- The token is a query parameter. It appears in Telegram links, report image URLs, and the brief's inline script.
- `/status`, `/cleanup`, `/screenshot`, and `/latest` are public. `/screenshot` can spend the daily browser quota. `/cleanup` closes sessions.
- Report HTML escapes model text. Brief HTML escapes model text. Telegram text is plain, not HTML.
- Failure webhook bodies are a small record (`runId`, `asset`, `date`, `error`). They do not include the API key or the viewer token.
- Telegram error text has the bot token replaced before it is logged via the thrown error.

This is a private morning tool with a shared secret in the URL, not an authenticated app.

`yarn test` is `tsx --test test/*.ts`. No browser, no DeepSeek, no KV. Covered:

- tiny PNG rejection, hash of a byte view, duplicate-hash policy, 3h to 30m fallback, interval readback
- schema example, fenced JSON, empty and truncated completions, chat body shape (`json_object`, thinking on, `detail: "original"`, no temperature, no tools, no `json_schema`)
- poor-capture report hides bias; empty citations warn only when capture is ok; HTML escaping
- cron params cannot force
- methodology and context stay separate files, and the client has no `file_search` and no temperature
- coerce of string lists and `{ name, price }` levels

## Gaps that are still real

1. **Chart roles do not match the method.** Capture is `1D`, `30m`, and `3h`. The checklist wants 4 hour or daily, 1 hour, 15 minute, and 1 minute. `15m` is intentionally absent from the label map. Expect `NO TRADE` unless the frames or the mandatory checklist change.
2. **One browser launch per timeframe**, not one session per asset. A full morning is up to six launches. The free-tier note in `/screenshot` still says 10 minutes of browser time per day. Quota exhaustion stops the rest of that asset's frames.
3. **Idempotent instance ids hide retries.** A failed `cron-YYYY-MM-DD` instance is not replaced by the next manual `/run` unless `force=1`.
4. **Cache hits trust the file.** A stored PNG is marked interval-verified without reading its metadata hash or dimensions.
5. **The range graphic is prose parsing.** It disappears when the model phrases the dealing range differently. Nothing in the schema requires those phrases.
6. **Four routes are public**, including live capture and session cleanup.
7. **The viewer token travels in query strings**, Telegram, and the brief's inline script. Gating is a shared secret plus 404, not a session.
8. **Docs besides this file will mislead the next reader.** They describe a project this tree has already passed.
9. **No live-widget or model integration test.** Selector drift on livecharts or TradingView fails at 07:00 UTC, not in CI.
10. **`FAILURE_WEBHOOK_URL` is outside the GitHub deploy secret set**, so a redeploy does not prove the webhook still exists.
